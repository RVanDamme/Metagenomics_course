Day 2: amplicon sequencing with DADA2

Author

Hadrien Gourlé, modified by Renaud Van Damme

This tutorial is aimed at being a walkthrough of the DADA2 pipeline. It uses the data of the now famous MiSeq SOP by the Mothur authors but analyses the data using DADA2.

DADA2 is a relatively new method to analyse amplicon data which uses exact variants instead of OTUs.

The advantages of the DADA2 method is described in the paper

Before Starting

There are two ways to follow this tutorial in RStudio:

  • copy and paste the code blocks below into R, one at a time; or
  • download this page as a notebook (right-click, “Save link as”), open it in RStudio and run the chunks one by one.

Install and Load Packages

This tutorial runs in RStudio, with R 4.5 or newer. Check your version with R.version.string.

First install DADA2 and the other packages. Run the lines one by one. The installation takes several minutes. If R asks “Update all/some/none?”, answer n (none).

if (!require("BiocManager", quietly = TRUE))
    install.packages("BiocManager")
BiocManager::install(c("dada2", "phyloseq", "DECIPHER"))
install.packages(c("ggplot2", "phangorn"))

BiocManager installs the version of DADA2 that belongs to your version of R: DADA2 1.38 with R 4.5, DADA2 1.40 with R 4.6. This tutorial was tested with DADA2 1.38.

Now load the packages and look at your DADA2 version. Write it down: it is part of your methods

library(dada2)
library(ggplot2)
library(phyloseq)
library(phangorn)
library(DECIPHER)
packageVersion('dada2')

Download the Data

You will also need to download the data, as well as the SILVA database. The downloads are done from R, so this works the same way on Windows, macOS and Linux. The files are saved in your current working directory (check it with getwd()).

# large files: allow up to 10 minutes per download
options(timeout = 600)

# the MiSeq SOP data (37 MB)
download.file('https://mothur.s3.us-east-2.amazonaws.com/wiki/miseqsopdata.zip',
              'miseqsopdata.zip', mode = 'wb')
# check that the download is complete:
# the result must be 98144f5057628139271d94612bb27d96
tools::md5sum('miseqsopdata.zip')
unzip('miseqsopdata.zip')

# the SILVA reference files (release 138.2), placed in the data folder
# 140 MB and 70 MB: this can take a few minutes
download.file('https://zenodo.org/records/14169026/files/silva_nr99_v138.2_toGenus_trainset.fa.gz',
              'MiSeq_SOP/silva_nr99_v138.2_toGenus_trainset.fa.gz', mode = 'wb')
download.file('https://zenodo.org/records/14169026/files/silva_v138.2_assignSpecies.fa.gz',
              'MiSeq_SOP/silva_v138.2_assignSpecies.fa.gz', mode = 'wb')
# check the downloads: the results must be
# 1764e2a36b4500ccb1c7d5261948a414 and 62fd939bd1aa9832d2089847f9f0b87d
tools::md5sum(c('MiSeq_SOP/silva_nr99_v138.2_toGenus_trainset.fa.gz',
                'MiSeq_SOP/silva_v138.2_assignSpecies.fa.gz'))

Then check that you have downloaded the data

path <- 'MiSeq_SOP'
list.files(path)

Filtering and Trimming

First we create two lists with the sorted name of the reads: one for the forward reads, one for the reverse reads

raw_forward <- sort(list.files(path, pattern="_R1_001.fastq",
                               full.names=TRUE))

raw_reverse <- sort(list.files(path, pattern="_R2_001.fastq",
                               full.names=TRUE))

# we also need the sample names
sample_names <- sapply(strsplit(basename(raw_forward), "_"),
                       `[`,  # extracts the first element of a subset
                       1)

then we visualise the quality of our reads

plotQualityProfile(raw_forward[1:2])
plotQualityProfile(raw_reverse[1:2])

The forward reads are good quality (although dropping a bit at the end as usual) while the reverse are way worse.

Based on these profiles, we will truncate the forward reads at position 240 and the reverse reads at position 160 where the quality distribution crashes.

Dada2 requires us to define the name of our output files

# place filtered files in filtered/ subdirectory
filtered_path <- file.path(path, "filtered")

filtered_forward <- file.path(filtered_path,
                              paste0(sample_names, "_R1_trimmed.fastq.gz"))

filtered_reverse <- file.path(filtered_path,
                              paste0(sample_names, "_R2_trimmed.fastq.gz"))

We’ll use standard filtering parameters: maxN=0 (DADA22 requires no Ns), truncQ=2, rm.phix=TRUE and maxEE=2. The maxEE parameter sets the maximum number of “expected errors” allowed in a read, which according to the USEARCH authors is a better filter than simply averaging quality scores.

out <- filterAndTrim(raw_forward, filtered_forward, raw_reverse,
                     filtered_reverse, truncLen=c(240,160), maxN=0,
                     maxEE=c(2,2), truncQ=2, rm.phix=TRUE, compress=TRUE,
                     multithread=TRUE)
head(out)

Learn the Error Rates

The DADA2 algorithm depends on a parametric error model and every amplicon dataset has a slightly different error rate. The learnErrors of Dada2 learns the error model from the data and will help DADA2 to fits its method to your data

errors_forward <- learnErrors(filtered_forward, multithread=TRUE)
errors_reverse <- learnErrors(filtered_reverse, multithread=TRUE)

then we visualise the estimated error rates

plotErrors(errors_forward, nominalQ=TRUE) +
    theme_minimal()

Dereplication

From the Dada2 documentation:

Dereplication combines all identical sequencing reads into into “unique sequences” with a corresponding “abundance”: the number of reads with that unique sequence. Dereplication substantially reduces computation time by eliminating redundant comparisons.

derep_forward <- derepFastq(filtered_forward, verbose=TRUE)
derep_reverse <- derepFastq(filtered_reverse, verbose=TRUE)
# name the derep-class objects by the sample names
names(derep_forward) <- sample_names
names(derep_reverse) <- sample_names

Sample inference

We are now ready to apply the core sequence-variant inference algorithm to the dereplicated data.

dada_forward <- dada(derep_forward, err=errors_forward, multithread=TRUE)
dada_reverse <- dada(derep_reverse, err=errors_reverse, multithread=TRUE)

# inspect the dada-class object
dada_forward[[1]]

The DADA2 algorithm inferred 128 real sequence variants from the 1979 unique sequences in the first sample.

Merge Paired-end Reads

Now that the reads are trimmed, dereplicated and error-corrected we can merge them together

merged_reads <- mergePairs(dada_forward, derep_forward, dada_reverse,
                           derep_reverse, verbose=TRUE)

# inspect the merger data.frame from the first sample
head(merged_reads[[1]])

Construct Sequence Table

We can now construct a sequence table of our mouse samples, a higher-resolution version of the OTU table produced by traditional methods.

seq_table <- makeSequenceTable(merged_reads)
dim(seq_table)

# inspect distribution of sequence lengths
table(nchar(getSequences(seq_table)))

Remove Chimeras

The dada method used earlier removes substitutions and indel errors but chimeras remain. We remove the chimera with

seq_table_nochim <- removeBimeraDenovo(seq_table, method='consensus',
                                       multithread=TRUE, verbose=TRUE)
dim(seq_table_nochim)

# which percentage of our reads did we keep?
sum(seq_table_nochim) / sum(seq_table)

As a final check of our progress, we’ll look at the number of reads that made it through each step in the pipeline

get_n <- function(x) sum(getUniques(x))

track <- cbind(out, sapply(dada_forward, get_n), sapply(merged_reads, get_n),
               rowSums(seq_table), rowSums(seq_table_nochim))

colnames(track) <- c('input', 'filtered', 'denoised', 'merged', 'tabled',
                     'nonchim')
rownames(track) <- sample_names
head(track)

We kept the majority of our reads!

Check the Result with the Mock Community

One of the samples, Mock, is not a mouse sample. It is a mock community: a mix of about 20 known bacterial strains, prepared in the laboratory and sequenced together with the real samples. We know what it contains, so we can check what our analysis does.

The file HMP_MOCK.v35.fasta of the data folder contains the true sequences of these strains.

# the sequence variants found in the Mock sample
mock_asvs <- seq_table_nochim['Mock', ]
mock_asvs <- sort(mock_asvs[mock_asvs > 0], decreasing=TRUE)
length(mock_asvs)

# how many of them are exactly identical to a true sequence?
mock_ref <- getSequences(file.path(path, 'HMP_MOCK.v35.fasta'))
is_exact <- sapply(names(mock_asvs),
                   function(x) any(grepl(x, mock_ref, fixed=TRUE)))
sum(is_exact)

# how many reads are in sequence variants that match no true sequence?
sum(mock_asvs[!is_exact])
TipQuestion

How many sequence variants did DADA2 find in the mock community? How many are exact matches to a true sequence? What does this tell you about the errors that remain after the whole analysis?

TipQuestion

A mock community can show two kinds of problems: sequences that should not be there, and strains that are missing. Which of the two did we check here? How would you check the other one?

Assign Taxonomy

Now we assign taxonomy to our sequences using the SILVA database, release 138.2. The first step compares each sequence with the reference and gives a name down to the genus. The second step adds a species name only when the sequence is exactly identical to a reference sequence.

Warning

This step needs about 5 GB of memory and takes a few minutes. RStudio runs on your own system, not in WSL. On a Windows laptop with 8 GB, first give the memory of WSL back to Windows: close the Ubuntu terminals and run wsl --shutdown in PowerShell. Close the other programs too.

taxa <- assignTaxonomy(seq_table_nochim,
                       'MiSeq_SOP/silva_nr99_v138.2_toGenus_trainset.fa.gz',
                       multithread=TRUE)
taxa <- addSpecies(taxa, 'MiSeq_SOP/silva_v138.2_assignSpecies.fa.gz')
Note

The names depend on the release of the database. SILVA 138.2 uses the current names of the phyla, the same as the Kraken 2 database of Day 1: Bacillota (before: Firmicutes), Bacteroidota (Bacteroidetes), Pseudomonadota (Proteobacteria), Actinomycetota (Actinobacteria). Older tutorials and papers, and the Galaxy version of this tutorial (SILVA 132), show the old names for the same organisms.

for inspecting the classification

taxa_print <- taxa  # removing sequence rownames for display only
rownames(taxa_print) <- NULL
head(taxa_print)

Phylogenetic Tree

DADA2 is reference-free so we have to build the tree ourselves

We first align our sequences

# use the table without chimeras: a chimera is not a real sequence and has no place in the tree
sequences <- getSequences(seq_table_nochim)
names(sequences) <- sequences  # this propagates to the tip labels of the tree
alignment <- AlignSeqs(DNAStringSet(sequences), anchor=NA)

Then we build a neighbour-joining tree then fit a maximum likelihood tree using the neighbour-joining tree as a starting point. This is the longest step of the tutorial: about 5 to 10 minutes.

phang_align <- phyDat(as(alignment, 'matrix'), type='DNA')
dm <- dist.ml(phang_align)
treeNJ <- NJ(dm)  # note, tip order != sequence order
fit = pml(treeNJ, data=phang_align)

# negative edges length changed to 0!

fitGTR <- update(fit, k=4, inv=0.2)
fitGTR <- optim.pml(fitGTR, model='GTR', optInv=TRUE, optGamma=TRUE,
                    rearrangement='stochastic',
                    control=pml.control(trace=0))
detach('package:phangorn', unload=TRUE)

Phyloseq

First load the metadata

sample_data <- read.table(
    'https://hadrieng.github.io/tutorials/data/16S_metadata.txt',
    header=TRUE, row.names="sample_name")

We can now construct a phyloseq object from our output and newly created metadata

physeq <- phyloseq(otu_table(seq_table_nochim, taxa_are_rows=FALSE),
                   sample_data(sample_data),
                   tax_table(taxa),
                   phy_tree(fitGTR$tree))
# remove the mock sample: we have used it above, it is not part of the mouse experiment
physeq <- prune_samples(sample_names(physeq) != 'Mock', physeq)
physeq

Let’s look at the alpha diversity of our samples: the number of sequence variants observed in each sample (Observed) and the Shannon index, which also takes into account how evenly the reads are spread over the variants.

plot_richness(physeq, x='day', measures=c('Observed', 'Shannon'), color='when') +
    theme_minimal()
Note

Other richness measures, such as Chao1, ACE or Fisher’s alpha, estimate the number of unseen variants from the variants that were seen only once (singletons). DADA2 removes singletons, because it cannot tell them from errors. So these measures have no meaning on a DADA2 table: do not use them here. This is also why plot_richness prints a warning about singletons: with DADA2 data, the warning is expected.

No obvious differences. Let’s look at ordination methods (beta diversity)

We can perform an MDS with euclidean distance (mathematically equivalent to a PCA)

ord <- ordinate(physeq, 'MDS', 'euclidean')
plot_ordination(physeq, ord, type='samples', color='when',
                title='MDS (PCoA) with Euclidean distance, MiSeq SOP samples') +
    theme_minimal()

now with the Bray-Curtis distance, and another ordination method (NMDS). This plot is not a PCA: its axes have no unit, only the distances between the points matter.

ord <- ordinate(physeq, 'NMDS', 'bray')
plot_ordination(physeq, ord, type='samples', color='when',
                title='NMDS with Bray-Curtis distance, MiSeq SOP samples') +
    theme_minimal()

There we can see a clear difference between our samples.

Let us take a look a the distribution of the most abundant families

top20 <- names(sort(taxa_sums(physeq), decreasing=TRUE))[1:20]
physeq_top20 <- transform_sample_counts(physeq, function(OTU) OTU/sum(OTU))
physeq_top20 <- prune_taxa(top20, physeq_top20)
plot_bar(physeq_top20, x='day', fill='Family') +
    facet_wrap(~when, scales='free_x') +
    theme_minimal()

We can place the sequences of one phylum, here the Bacteroidota, in a tree

bacteroidota <- subset_taxa(physeq, Phylum %in% c('Bacteroidota'))
plot_tree(bacteroidota, ladderize='left', size='abundance',
          color='when', label.tips='Family')
