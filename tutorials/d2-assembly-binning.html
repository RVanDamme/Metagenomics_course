Day 2: metagenome assembly and binning

ImportantBefore you start

Do the Setup first. Then open a terminal and activate the tools of the course:

cd ~/mag2026/Metagenomics_course
pixi shell

In this tutorial you’ll learn how to inspect assemble metagenomic data and retrieve draft genomes from assembled metagenomes

We’ll use a mock community of 10 bacteria sequenced using the Illumina HiSeq. In reality the data were simulated using InSilicoSeq.

The 10 bacteria in the dataset were selected from the Tara Ocean study that recovered 957 distinct Metagenome-assembled-genomes (or MAGs) that were previsouly unknown! (full list on figshare )

Prepare and organise your working directory

All the work of this tutorial is done in the folder ~/mag2026/d2, organised like the one of Day 1: the reads go in data/, everything you compute goes in results/. Every command below is run from ~/mag2026/d2, unless the text says otherwise.

mkdir -p ~/mag2026/d2
cd ~/mag2026/d2
mkdir data
mkdir results

If you close your terminal and come back later, activate the tools again (see the top of this page) and return to the folder with cd ~/mag2026/d2.

Getting the Data

cd ~/mag2026/d2/data
curl -f -O -J -L https://osf.io/th9z6/download
curl -f -O -J -L https://osf.io/k6vme/download
chmod -w tara_reads_R*
cd ~/mag2026/d2

The two files of reads are now in data/. The chmod -w command protects them: they can be read, but not changed or deleted by mistake.

NoteIf the download fails

The option -f makes curl stop with an error message (for example curl: (22) The requested URL returned error: 500) when the server has a problem. Without it, curl would save the error page of the server under the name of the file, and the next command would fail in a confusing way. If you see such an error, wait a few minutes and run the command again, or copy the file from the drive of your teacher. The Data page gives the checksum of every file.

Quality Control

we’ll use FastQC to check the quality of our data, as well as sickle for trimming the bad quality part of the reads.

mkdir -p results/fastqc
fastqc --outdir results/fastqc data/tara_reads_*.fastq.gz

Open the two reports of results/fastqc in your web browser.

Now we’ll trim the reads using sickle

sickle pe -f data/tara_reads_R1.fastq.gz -r data/tara_reads_R2.fastq.gz -t sanger \
    -o results/tara_trimmed_R1.fastq -p results/tara_trimmed_R2.fastq -s /dev/null
TipQuestion

How many reads were trimmed?

Assembly

Megahit will be used for the assembly.

megahit -1 results/tara_trimmed_R1.fastq -2 results/tara_trimmed_R2.fastq -o results/tara_assembly

the resulting assembly can be found under results/tara_assembly/final.contigs.fa.

How many contigs does this assembly contain?

Binning

First we need to map the reads back against the assembly to get coverage information. We map the trimmed reads, the same reads that were used for the assembly. The mapping takes about 4 minutes.

bowtie2-build results/tara_assembly/final.contigs.fa results/final.contigs
bowtie2 -p 2 -x results/final.contigs \
    -1 results/tara_trimmed_R1.fastq -2 results/tara_trimmed_R2.fastq | \
    samtools view -bS -o results/tara_to_sort.bam
samtools sort results/tara_to_sort.bam -o results/tara.bam
samtools index results/tara.bam

then we run metabat

runMetaBat.sh -m 1500 --seed 1 results/tara_assembly/final.contigs.fa results/tara.bam
mv final.contigs.fa.metabat-bins* results/metabat
mv final.contigs.fa.depth.txt results/
NoteWhy --seed 1?

MetaBAT 2 makes some of its choices at random. Without a seed, two runs on exactly the same files give slightly different bins: a few contigs change bin. The option --seed fixes the starting point of the random choices (any number works; we all use 1), so the same input gives the same bins every time.

In this course we fix the seed so that everybody gets bins with the same content, and we can discuss them together.

One thing still differs between laptops: the numbers of the bins. The assembler gives its contigs other names, in another order, at each run, so your bin.3 can be the bin.7 of your neighbour, with exactly the same contigs inside. To recognise a bin, look at its size and its number of contigs, not at its number:

seqkit stats results/metabat/bin.*.fa

In a research project the answer has two parts.

  • Do fix the seed and write it in your methods, with the version of the tool: without it, nobody can reproduce your bins exactly, not even you.
  • Do not believe that a fixed seed makes the bins more correct. It only hides the variation. To see it, run the binning a few times with different seeds: the bins that stay the same are robust, and the contigs that move from one bin to another are uncertain.

And never try several seeds to keep the one that gives the result you prefer.

MetaBAT 2 writes its output in the current folder: a table with the coverage of each contig (final.contigs.fa.depth.txt) and a folder of bins, whose name ends with the date and time of the run. The two mv commands put them in results/, and rename the folder of bins to metabat. Each bin is one FASTA file, bin.1.fa, bin.2.fa, and so on.

Checking the quality of the bins

A bin is only a draft genome. Before using it, we estimate two numbers:

  • completeness: which part of the genome is in the bin;
  • contamination: how much of the bin comes from other genomes.

Nobody knows the true genome, so both numbers are estimates. They are based on genes that almost every bacterium has in exactly one copy (single-copy marker genes): a missing marker lowers the completeness, a marker found twice raises the contamination.

We will use two tools that make this estimate in different ways, and compare them:

  • CheckM (version 1) places each bin in a reference tree and counts the marker genes of its lineage;
  • CheckM2 predicts the two numbers with machine-learning models trained on many genomes.

Each tool has its own environment and its own reference data.

CheckM

Open a second terminal and activate the CheckM environment:

cd ~/mag2026/Metagenomics_course
pixi shell -e checkm1
cd ~/mag2026/d2

The first time you run checkm you have to get its reference data (289 MB; ask your teacher for the drive copy) and tell CheckM where they are:

mkdir -p ~/mag2026/databases/checkm_data
cd ~/mag2026/databases/checkm_data
curl -f -O https://data.ace.uq.edu.au/public/CheckM_databases/checkm_data_2015_01_16.tar.gz
# check the download: the result must be 631012fa598c43fdeb88c619ad282c4d
md5sum checkm_data_2015_01_16.tar.gz
tar -xzf checkm_data_2015_01_16.tar.gz
rm checkm_data_2015_01_16.tar.gz
checkm data setRoot ~/mag2026/databases/checkm_data
cd ~/mag2026/d2

Now run CheckM on the folder of bins (about 5 minutes):

checkm lineage_wf -t 2 --gplace_max_memory 2G -x fa results/metabat results/checkm
checkm qa results/checkm/lineage.ms results/checkm --tab_table -f results/checkm.tsv
Note

--gplace_max_memory 2G limits the memory of the step that places the bins in the reference tree. Without this limit, CheckM needs far more memory than a laptop has and is stopped by the system (“Killed”).

The result is the table results/checkm.tsv. Columns 12 and 13 are the completeness and the contamination:

cut -f1,12,13 results/checkm.tsv

The other columns give the lineage that CheckM chose for the bin, and how many marker genes were found 0, 1, 2 or more times.

CheckM2

In the same second terminal, leave the CheckM environment and activate the CheckM2 environment:

exit
pixi shell -e checkm2
cd ~/mag2026/d2

The first time, get the CheckM2 database (1.7 GB to download, 2.9 GB on disk; ask your teacher for the drive copy):

cd ~/mag2026/databases
curl -f -L -o checkm2_database.tar.gz "https://zenodo.org/records/14897628/files/checkm2_database.tar.gz?download=1"
# check the download: the result must be 07c10655620843b517d0df0c160d911f
md5sum checkm2_database.tar.gz
tar -xzf checkm2_database.tar.gz
rm checkm2_database.tar.gz
cd ~/mag2026/d2

Run CheckM2 on the same bins (about 8 minutes):

checkm2 predict --lowmem --threads 2 -x fa \
    --input results/metabat --output-directory results/checkm2 \
    --database_path ~/mag2026/databases/CheckM2_database/uniref100.KO.1.dmnd
Note

--lowmem makes CheckM2 use less memory, at the price of a longer run. Without it, CheckM2 does not fit in 6 GB.

The result is the table results/checkm2/quality_report.tsv. Its first three columns are the name of the bin, the completeness and the contamination:

cut -f1-3 results/checkm2/quality_report.tsv

Compare the two tools

Put the completeness and contamination of both tools side by side, for example in a spreadsheet or on paper.

TipQuestion

Do CheckM and CheckM2 agree? For which bins do they differ the most?

TipQuestion

The two tools were given exactly the same bins. Why can their estimates differ? Which one is “right”?

To decide which bins are good enough, many studies use the MIMAG standard (Bowers et al. 2017):

Quality Completeness Contamination Also required
High-quality draft more than 90% less than 5% the 23S, 16S and 5S rRNA genes and at least 18 tRNAs
Medium-quality draft 50% or more less than 10%
Low-quality draft less than 50% less than 10%
TipQuestion

Which bins should we keep for downstream analysis? Give each bin its MIMAG quality, once with the CheckM values and once with the CheckM2 values. Does a bin change category?

TipQuestion

Both tools estimate contamination from marker genes that are found more than once. Imagine a bin that contains a few contigs of another organism, and these contigs carry no marker gene. What would the tools report? What does this tell you about a contamination of “2%”?

Note

Our reads were simulated from 10 known genomes, and the name of each read still says which genome it comes from. So for this dataset the truth can be checked. Ask your teacher how the bins compare with the truth, after you have answered the questions.

NoteIf CheckM or CheckM2 does not run on your laptop

Tell your teacher. There are two other ways to get the results:

  1. Result files. The teacher gives you checkm.tsv and quality_report.tsv, computed on the same data. Use them for the comparison.
  2. Galaxy. Upload your 10 bin files (results/metabat/bin.*.fa, 20 MB) to usegalaxy.eu, make a collection of them, and run the tools “CheckM lineage_wf” and “CheckM2” on it.

When you have finished, close the second terminal, or type exit to leave the environment.

Functional annotation

Now we should have a collection of MAGs that we can further analyze. The first step is to predict genes as right now we only have raw genomic sequences. We will use Prokka, a widely used annotation tool for prokaryotic genomes.

This tool does gene prediction as well as some decent and useful annotations, and is actually quite easy to run!

Prokka is in its own environment. Open a second terminal (or reuse the one of CheckM, after exit) and activate it:

cd ~/mag2026/Metagenomics_course
pixi shell -e prokka
cd ~/mag2026/d2

On a Mac with Apple Silicon, this environment runs through Rosetta: see Setup.

Choose one bin, for example a bin with a high completeness and a low contamination, and annotate it (about 3 minutes; replace bin.1 and bin1 by your choice):

prokka --cpus 2 --outdir results/prokka_bin1 --prefix bin1 results/metabat/bin.1.fa

Prokka produces a number of output files in the folder results/prokka_bin1, which mostly represent the same thing in different formats:

File Content
bin1.txt a summary: number of contigs, genes (CDS), tRNA and rRNA genes
bin1.faa the predicted proteins (FASTA). You need this file for eggNOG-mapper
bin1.ffn the predicted genes (FASTA, DNA)
bin1.gff the position and the annotation of every gene on the contigs
bin1.tsv a table with one line per gene

Prokka also renames all the sequences with nicer IDs.

cat results/prokka_bin1/bin1.txt
grep -c "hypothetical protein" results/prokka_bin1/bin1.faa
TipQuestion

How many genes (CDS) did Prokka find? How many of them are “hypothetical proteins”? What does “hypothetical” mean here?

TipQuestion

Every bacterium has rRNA genes (16S, 23S, 5S) and a full set of tRNA genes. Look at the summary of your bin: is something missing? Why would these genes be absent from a bin, even when the bin is almost complete?

eggNOG-mapper (on Galaxy)

The annotations of Prokka are good but not very complete for environmental bacteria. eggNOG-mapper compares each protein with the eggNOG database of groups of related genes (orthologous groups), and transfers their annotation: gene names, functional categories (COG), pathways (KEGG) and more. This is a bit heavier in computation.

The eggNOG database takes more than 40 GB, too much for a laptop. So this step runs on Galaxy, not on your computer.

  1. Choose one MAG (don’t be greedy, it is not fast!). You need its protein file: the .faa file that Prokka made for this MAG.
  2. Log in to usegalaxy.eu and upload the .faa file with the “Upload” button.
  3. Search the tool panel for “eggNOG Mapper” and run the tool on your file. Keep the default settings.
  4. Wait until the job is green, then open the annotation table.

usegalaxy.eu runs eggNOG-mapper 2.1.13 with version 5.0.2 of the eggNOG database. Write these two versions down: they are part of your result.

TipQuestion

OPTIONAL: understand the output. Find three proteins that Prokka named “hypothetical protein”. What does eggNOG-mapper say about them?

NoteIf Galaxy is slow or not available

The authors of eggNOG-mapper offer a web service: https://eggnog-mapper.cgmlab.org (the old address, eggnog-mapper.embl.de, sends you there). Upload the same .faa file and follow the instructions of the page. Submit your job early: jobs wait in a queue, and a job can take an hour or more. The web service uses a newer database (eggNOG 7), so some annotations differ from the Galaxy result.

Taxonomic annotation

We now know more about the genes your MAG contains, however we do not really know who we have?! checkm might have given us an indication but it is only approximative.

Taxonomic classification for full genomes is not always easy for MAGs, often the 16S gene is missing as it assembles badly, and which other genes to use to for taxonomy is not always evident. Typically marker genes, min-hashes or k-mer databases are used as reference. It is often problematic for environmental data as the databases are not biased into our direction! We will use a min-hash database of the GTDB representative genomes with a tool called sourmash.

GTDB is a taxonomy built from genomes. It contains one representative genome per species, including many species known only from MAGs. sourmash keeps a small “sketch” of each genome: a sample of its k-mers. Comparing two sketches is very fast.

Get the database

The database of this tutorial is a reduced copy of the sourmash database “GTDB R226, species representatives, k=31”, made for this course so that it fits in the memory of a laptop. Your teacher gives you the two files on a drive:

  • gtdb-reps-rs226-k31.s10k.zip (447 MB): the sketches of the 143,384 GTDB representative genomes;
  • gtdb-rs226.lineages.csv (103 MB): the taxonomy of each genome.

Copy them into ~/mag2026/databases/sourmash/. The Data page explains how the reduced file was made and how to rebuild it.

SOURMASH_DB=~/mag2026/databases/sourmash
ls $SOURMASH_DB

Sketch the bins and search the database

sourmash is in the main environment (the first terminal). For each bin we make a sketch (sourmash sketch), then search the genomes of the database that best explain it (sourmash gather). This takes about 1 minute per bin.

cd ~/mag2026/d2
mkdir -p results/sourmash
for i in results/metabat/bin.*.fa
do
    name=$(basename $i .fa)
    echo $name
    sourmash sketch dna -p k=31,scaled=10000 --name $name $i -o results/sourmash/${name}.sig
    sourmash gather results/sourmash/${name}.sig $SOURMASH_DB/gtdb-reps-rs226-k31.s10k.zip \
        -o results/sourmash/${name}.gather.csv
done

For each bin, gather prints the genomes it found and which part of the bin they explain. If nothing in the database is similar enough, it prints “No matches” and writes no file.

From genomes to a taxonomy

sourmash tax genome reads the matches and the taxonomy file, and gives one classification per bin:

sourmash tax genome -g results/sourmash/*.gather.csv -t $SOURMASH_DB/gtdb-rs226.lineages.csv \
    -o results/sourmash/bins --output-format csv_summary human
cat results/sourmash/bins.human.txt

The lineage is written with the GTDB prefixes: d__ domain, p__ phylum, c__ class, o__ order, f__ family, g__ genus, s__ species.

TipQuestion

How many bins received a classification? At which rank? Look at the species names: what do names such as sp002699365 tell you about these organisms?

TipQuestion

One bin has no match. Does that mean the bin is bad? Compare with its CheckM results before you answer.

The GTDB database is also used by the tool GTDB-Tk. It uses marker genes and places each genome in a reference tree. It is more sensitive, but its database is far too large for a laptop.

NoteOptional

Run GTDB-Tk on Galaxy: upload your bins to usegalaxy.eu and search the tool panel for “GTDB-Tk Classify genomes”. Compare its answer with the one of sourmash.
